# ShopOS Feed prototypes

One app concept, the **ShopOS Feed**, prototyped as single-page HTML apps and adapted for different brands. Each prototype is a static site (`index.html` plus `assets/`) with no build step. Open `index.html` in a browser, or run `python3 -m http.server` inside a prototype folder.

> Full documentation is coming. This README is only a map of the repo.

## Layout

| Path | What it is |
|------|------------|
| `prototypes/` | One folder per brand. `main` is the base prototype; the rest are brand adaptations of it. |
| `archive/prd/` | Old PRD iterations. They are well behind what the prototypes actually do. Treat them as history, not spec. |
| `archive/puma-oldsot/` | An earlier PUMA prototype built on a different pipeline and an older base. |
| `archive/point-taken-archive/` | Early Point Taken trial feed. |
| `docs/` | Supporting material: the Brand Feeds content sheet and a sample change set. |

## Prototypes

`angel-one`, `armani-exchange`, `cosmix`, `giva`, `holy-drip`, `larkspire`, `main`, `malaysia-airlines`, `point-taken`, `pointer`, `puma`, `r-for-rabbit`, `superdry`, `van-heusen`, `wework`.

Each folder has its own `README.md` and, in most cases, a `CHANGELOG.md`.

## How the brand adaptations were made

The brand prototypes were generated by an agent skill that took an existing prototype and re-skinned it for a new brand. The only required input was the brand's website. Social links, notes on how to navigate the brand's content, and extra reference links were optional. The agent could find the rest itself.

That skill is not in this repo, and the prototypes were made with an older version of it. They show the output, not the current process.
